# MISRA C:2012 rules that `scripts/cppcheck.py --misra` does not check, and why.
# One rule per line: its number, then the reason, or
#     <number> in <path pattern> <reason>
# for a rule that is not checked in the files the pattern matches (src/button/*.c).
# Take a line out to see what the rule would report.  A single place that breaks a rule which
# is otherwise kept has a `// cppcheck-suppress [misra-c2012-<number>] ; <reason>` above it
# in the source instead.

# Not checkable with this setup.
8.2    cppcheck's check reads the whole translation unit again for every function declared in it, the SDK's headers included: minutes per source
20.13  the sources reach cppcheck preprocessed by the compiler, and cppcheck takes its "# <line> <file>" markers for invalid directives
17.3   cppcheck does not know the compiler builtins that the SDK's macros (CONTAINER_OF, UNALIGNED_GET, __ASSERT, IRQ_DIRECT_CONNECT) expand to; the compiler warns about a real implicit declaration, and the build has no warnings

# Deviations: the firmware does not follow these.
1.2    Zephyr's macros (containers, logging, devicetree, sections) are built on GCC extensions
2.5    the register maps and protocol command tables are kept complete, whether or not the code uses every entry yet
2.7    a callback takes the parameters its table or the SDK prescribes, used or not
5.8    structure members share their names with the functions that read them (is_master, crc32) and with library functions (div)
5.9    Zephyr's registration macros (LOG_MODULE_REGISTER, BT_CONN_CB_DEFINE) define a static of one name in every file that uses them
8.7    the linker's --wrap targets, the hooks the SDK calls and Zephyr's definition macros need external linkage, and a module's interface stays in its header when only one other file calls it yet
8.9    file-scope state is reached by the unit tests, and the bitmap and font tables of a header are not moved into the one function that draws them
9.3    message and reply buffers are initialised with their first bytes; the language zeroes the rest
11.5   Zephyr hands thread arguments, callback contexts and device data around as void *
13.5   bounded waits count down inside their condition (while (busy && --retries))
14.2   parsers and the text renderer step a second cursor along with the loop counter, and retry loops count in their body
15.1   error paths that have something to free leave through a common label (the whitelist JSON, the touch driver's firmware update)
15.4   thread loops and the text layout loops have several ways out
15.5   early returns on errors are the style of this code and of Zephyr
16.3   a clause that ends in return, goto, continue or a call that does not return has no break, and the intended fall-throughs are marked (__fallthrough or a comment)
17.7   the results of printk, memcpy, memset, snprintf and the like are not used, and a (void) on each of some 2000 calls would bury the code; functions whose result must not be dropped are Zephyr's __must_check ones, which the compiler reports
18.4   packet parsing and frame buffer addressing use pointer arithmetic throughout
19.2   register words and protocol frames are overlaid with unions
21.3   the frame buffer, the JSON documents and the transfer buffers come from the heap
21.15  values are packed into and out of protocol byte buffers with memcpy
21.16  fixed-size name, text and address buffers are compared whole with memcmp, to tell whether anything in them changed
22.8   the debug commands take whatever strtol makes of their argument; there is no error reply to give
22.9   as 22.8
